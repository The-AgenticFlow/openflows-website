Workflow

How It Works

One cycle. From open issue to merged code.

01

Discover

NEXUS syncs open GitHub issues into the SharedStore as tickets (T-001, T-002...).

02

Assign

NEXUS matches priority tickets to idle FORGE workers (forge-1, forge-2).

03

Plan

FORGE writes PLAN.md with segment breakdown. SENTINEL reviews → CONTRACT.md (AGREED / CHANGES_REQUESTED).

04

Build

FORGE implements segment by segment. After each: commit + WORKLOG.md → SENTINEL eval → segment-N-eval.md.

05

Review

SENTINEL runs final review (final-review.md). APPROVED → FORGE opens PR.

06

Merge

VESSEL polls CI (10s interval). Green → squash merge. Conflicts → routes back to same FORGE worker.

07

Document

LORE writes ADRs and changelogs from merged work.

08

Loop

NEXUS picks the next ticket. No work left? Halt gracefully.

System Design

Built for Production

Rust async runtime. Zero-polling event loops. Git worktree isolation.

PILLAR 01

SharedStore

Dual-backend state: in-memory for dev/tests, Redis for production. All agents communicate through typed keys: tickets, worker_slots, pending_prs. A 1000-event ring buffer powers real-time TUI monitoring.

PILLAR 02

FORGE-SENTINEL Pair Harness

Each pair gets an isolated Git worktree on its own branch. File ownership is locked dynamically via flock. Hooks enforce auto-mode permissions: FORGE can commit but never git push directly — MCP tools handle the PR. SENTINEL is read-only and ephemeral.

PILLAR 03

Flow Recovery

NEXUS detects orphaned tickets, stale workers, and unmerged PRs on every cycle. Three consecutive no_work decisions halt the loop. Conflict rework routes directly VESSEL → FORGE without losing context.

Capabilities

What Makes It Different

Auto Mode Permissions

Claude Code runs with declarative allow/deny lists. FORGE can test and lint; SENTINEL is read-only. Security through constraints, not prompts.

Dynamic File Locking

pre_write_check.sh intercepts every write. Files are locked per-pair via flock. Race conditions eliminated at the filesystem level.

Secret Scrubbing

Before every push, scan_and_scrub_secrets() redacts known patterns. If GH013 rejects, history is rewritten with git filter-branch.

Per-Agent Model Routing

LiteLLM proxy routes each agent to the best model for its task. FORGE → Claude Sonnet. SENTINEL → Gemini Pro. VESSEL → Groq (free tier).

Conflict Rework Loop

Merge conflicts don't create new PRs. VESSEL writes CONFLICT_RESOLUTION.md, re-assigns the same worker, and re-monitors CI.

ReAct Nexus (Coming)

NEXUS will follow iterative Reason→Act→Observe loops for human chat commands, with RAG context injection.

Deployment

Get Started in 60 Seconds

STEP 01

Install

npm install -g @the-agenticflow/openflows
openflows --version
STEP 02

Configure

openflows-setup
# Or manually edit .env with your keys:
GITHUB_REPOSITORY=your-org/your-repo
GITHUB_PERSONAL_ACCESS_TOKEN=ghp_xxx
ANTHROPIC_API_KEY=sk-ant-xxx
STEP 03

Run

openflows-setup
openflows
# Monitor (optional, separate terminal):
openflows-dashboard
# Diagnose issues:
openflows-doctor

Requirements: Node.js 18+ · npm · Claude Code CLI · GitHub PAT with repo + workflow scopes
