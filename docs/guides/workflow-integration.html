Workflow Integration

Connect Openflows to your existing development workflows — GitHub Actions, CI/CD pipelines, code review gates, and notification systems.

GitHub Actions Integration

Add Openflows as a GitHub Action to run autonomously on repository events:

yaml
name: Openflows Auto-PR
on:
  issues:
    types: [opened, labeled]
  schedule:
    - cron: '*/30 * * * *'  # Check every 30 minutes

jobs:
  auto-pr:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run Openflows
        uses: The-AgenticFlow/Openflows@main
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          openai-api-key: ${{ secrets.OPENAI_API_KEY }}
          config-path: ./openflows.toml

Webhook Events

Openflows responds to these GitHub webhook events:

EventTriggerAgent Action
issuesNew issue openedNEXUS triages and assigns to FORGE
pull_requestNew PR createdSENTINEL begins code review
pushCode pushed to mainVESSEL runs build and tests
issue_commentComment on issueNEXUS re-evaluates priority
labelLabel added/removedNEXUS triggers relevant workflow

CI/CD Pipeline Integration

Openflows integrates with popular CI/CD systems:

bash
# Run Openflows as part of your CI pipeline
openflows daemon start --ci-mode

# CI mode behaviors:
# - No interactive prompts
# - Structured JSON output
# - Exits with code 0 on success, 1 on failure
# - Respect SENTINEL review gates

Review Gates

Control when human approval is required:

toml
[review_gates]
# Require human approval for PRs touching these paths
require_approval_patterns = [
    "src/core/**",
    "Cargo.toml",
    "migrations/**"
]

# Auto-approve if SENTINEL score is above threshold
auto_approve_threshold = 0.85

# Always require approval for these file types
require_approval_extensions = [".sql", ".env"]
⚠️ Security

Never commit API keys to your repository. Use GitHub Secrets for sensitive tokens. The GITHUB_TOKEN is automatically available in Actions but needs repo and workflow scopes for Openflows.

Notification Integrations

Configure where Openflows sends status updates:

toml
[notifications]
# Slack webhook for agent status updates
slack_webhook = "https://hooks.slack.com/services/..."

# Email alerts for blocked agents
email = "dev-team@example.com"

# GitHub commit status updates (enabled by default)
github_status = true
