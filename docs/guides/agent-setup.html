Agent Setup

Openflows operates through five specialized agent roles, each with a distinct responsibility. This guide explains how to configure each agent for your project.

Agent Roles Overview

AgentRoleResponsibilityDefault Model
NEXUSCoordinatorTriages issues, assigns tasks, manages workflowgpt-4o
FORGEBuilderWrites implementation code for assigned tasksgpt-4o
SENTINELReviewerReviews code quality, correctness, and safetygpt-4o
LOREHistorianMaintains institutional knowledge and contextgpt-4o
VESSELCarrierManages environment, deployment, and infrastructuregpt-4o

Configuration File

Agent configuration lives in openflows.toml at the root of your project:

toml
[agents.nexus]
model = "gpt-4o"
system_prompt = "You are NEXUS, the coordinator. Triage issues by priority and assign to FORGE workers."
max_tokens = 4096
temperature = 0.3

[agents.forge]
model = "gpt-4o"
system_prompt = "You are FORGE, a builder agent. Write clean, tested code."
max_tokens = 8192
temperature = 0.2

[agents.sentinel]
model = "gpt-4o"
system_prompt = "You are SENTINEL, a reviewer. Check code for bugs, style violations, and security issues."
max_tokens = 4096
temperature = 0.1

[agents.lore]
model = "gpt-4o"
system_prompt = "You are LORE, the historian. Maintain context about the project's decisions and architecture."
max_tokens = 2048
temperature = 0.4

[agents.vessel]
model = "gpt-4o"
system_prompt = "You are VESSEL, the carrier. Manage build, test, and deployment pipelines."
max_tokens = 2048
temperature = 0.2

Custom System Prompts

Each agent's system_prompt shapes its behavior. Some customization ideas:

  • FORGE — Add project-specific coding conventions, preferred libraries, or architectural patterns
  • SENTINEL — Emphasize specific security policies, code style rules, or test coverage thresholds
  • NEXUS — Define priority heuristics: label-based triage, effort estimation, or skill matching
💡 Tip

Start with the default prompts and iterate. Review the agent outputs in early runs and refine prompts based on observed behavior.

Model Selection

Each agent can use a different LLM provider and model:

toml
[agents.forge]
model = "claude-3-opus-20240229"
provider = "anthropic"
api_key_env = "ANTHROPIC_API_KEY"

[agents.sentinel]
model = "gpt-4o"
provider = "openai"

Permission Boundaries

Control what each agent can do:

toml
[permissions.forge]
allow = ["Read", "Write", "Bash", "GitPush"]
deny = ["Slack"]  # No Slack notifications from builders

[permissions.sentinel]
allow = ["Read", "Bash"]  # Reviewers only read and run tests
deny = ["Write", "GitPush"]  # Cannot write code or push
