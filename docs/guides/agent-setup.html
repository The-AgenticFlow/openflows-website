Agent Setup

OpenFlows agents are configured through two files: .env for API keys and runtime settings, and orchestration/agent/registry.json for team membership, worker scaling, and per-agent model routing. Run openflows-setup to generate both interactively.

registry.json — The Single Source of Truth

This file defines which agents are active, how many parallel workers each gets, which model backend to use, and which GitHub token to use per agent.

json
{
  "default_cli": "codex",
  "team": [
    {
      "id": "nexus",
      "cli": "codex",
      "active": true,
      "instances": 1,
      "model_backend": "accounts/fireworks/models/kimi-k2p5",
      "routing_key": "nexus-key",
      "github_token_env": "AGENT_NEXUS_GITHUB_TOKEN"
    },
    {
      "id": "forge",
      "cli": "codex",
      "active": true,
      "instances": 2,
      "model_backend": "accounts/fireworks/models/kimi-k2p5",
      "routing_key": "forge-key",
      "github_token_env": "AGENT_FORGE_GITHUB_TOKEN"
    },
    {
      "id": "sentinel",
      "cli": "claude",
      "active": true,
      "instances": 1,
      "model_backend": "anthropic/claude-sonnet-4-5",
      "routing_key": "sentinel-key",
      "github_token_env": "AGENT_SENTINEL_GITHUB_TOKEN"
    },
    {
      "id": "vessel",
      "cli": "codex",
      "active": true,
      "instances": 1,
      "model_backend": "groq/llama-3.3-70b-versatile",
      "routing_key": "vessel-key",
      "github_token_env": "AGENT_VESSEL_GITHUB_TOKEN"
    },
    {
      "id": "lore",
      "cli": "codex",
      "active": true,
      "instances": 1,
      "model_backend": "openai/gpt-4o-mini",
      "routing_key": "lore-key",
      "github_token_env": "AGENT_LORE_GITHUB_TOKEN"
    }
  ]
}

Registry Fields

FieldTypeDescription
idstringAgent name. Used in logs, worktree names (forge-1), and branch names.
clistring"codex" or "claude" — which CLI to spawn for this agent.
activeboolSet false to exclude the agent from orchestration entirely.
instancesintNumber of parallel worker slots. FORGE with instances: 2 → forge-1, forge-2.
model_backendstringModel identifier passed to the LLM client or LiteLLM proxy.
routing_keystringLiteLLM proxy routing key. Maps to a backend model in litellm_config.yaml.
github_token_envstringEnv var name holding this agent's GitHub PAT. Falls back to GITHUB_PERSONAL_ACCESS_TOKEN.

Common Operations

Scale FORGE workers:

json
{ "id": "forge", "instances": 4 }  // → forge-1, forge-2, forge-3, forge-4

Disable an agent:

json
{ "id": "lore", "active": false }  // LORE will not be invoked

Per-agent GitHub tokens (for rate limit isolation and scope restriction):

bash
export AGENT_NEXUS_GITHUB_TOKEN=ghp_nexus_token
export AGENT_FORGE_GITHUB_TOKEN=ghp_forge_token
export AGENT_SENTINEL_GITHUB_TOKEN=ghp_sentinel_token
export AGENT_VESSEL_GITHUB_TOKEN=ghp_vessel_token
export AGENT_LORE_GITHUB_TOKEN=ghp_lore_token

Recommended Model Assignments

AgentRecommended ModelWhy
FORGEclaude-sonnet-4-5 or kimi-k2p5Primary coding agent — needs top-tier reasoning
NEXUSclaude-sonnet-4-5 or kimi-k2p5Orchestrator — needs reliable decision-making
SENTINELgemini-2.5-proCode review — strong reasoning at lower cost
VESSELgroq/llama-3.3-70b-versatileCI/CD scripting — fast and cheap (free tier)
LOREgpt-4o-miniDocumentation — lightweight task
ℹ️ Hot Reload

registry.json is re-read on every NEXUS poll cycle — no restart required when you change instances, models, or active flags.
