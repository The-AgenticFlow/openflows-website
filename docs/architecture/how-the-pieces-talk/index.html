How the pieces talk

Manager owns privileged control-plane decisions. Nexus owns the tenant's agent workflow. Coder runs workspaces, and Redis stores tenant coordination state. The channel determines the credential and authority.

ChannelAuthenticationWhat travels over it
Nexus → ManagerWorkspace runtime access tokenWorker requests, status, heartbeats, and GitHub credential requests
Manager → CoderPlatform operator credentialTemplate publication and workspace creation or lifecycle
Runtime → RedisTenant Redis ACL credentialTicket state, worker slots, heartbeats, A2A evidence
Coder → Manager → NexusGlobal then tenant hook JWTCoder lifecycle events and policy responses
Forge / Sentinel → NexusTicket pair tokenA2A verification tasks, progress, and results
Runtime → GitHubBrokered installation tokenRepository API and Git operations

Runtime API

Each workspace registers using a one-time bootstrap and receives an access/refresh pair. Manager derives its tenant, role, and repository from the workspace record. Nexus asks Manager to create workers; Manager records a durable operation and talks to Coder.

Hooks and A2A

Coder lifecycle events enter through Manager, which authenticates and routes them to the tenant's Nexus hook server. Agent CLI hooks run locally inside worker workspaces. Sentinel and Forge exchange verification tasks through Nexus's A2A relay, which persists evidence to tenant Redis.

Read Manager Runtime, Credentials and Trust, and Hooks and A2A for the full request flows.
