Workflow Walkthrough

Follow a complete Openflows workflow from start to finish. Each step shows what happens, what the agents do, and what code is involved.

Create GitHub Issue
A team member creates a GitHub issue describing a bug or feature request. The issue includes a title, description, and labels.
markdown
## Bug: Pagination returns wrong results for page 2+

**Labels:** bug, priority:high

The API endpoint `GET /api/v1/items` returns duplicate
items when requesting page 2 or higher. The offset
calculation appears to be off by one.

Expected: `offset = (page - 1) * per_page`
Actual: `offset = page * per_page`
NEXUS Triages the Issue
NEXUS reads the issue, evaluates its scope and priority, and creates a structured task definition.
json
{
  "task_id": "T-142",
  "issue_number": 142,
  "priority": "HIGH",
  "type": "bug_fix",
  "scope": "src/api/pagination.rs",
  "acceptance_criteria": [
    "Fix offset calculation to (page - 1) * per_page",
    "Add unit tests for boundary cases",
    "No regression on page 1"
  ],
  "assigned_to": "forge-1"
}
FORGE Reads Context & Plans
FORGE reads the relevant files, understands the existing code, and plans the implementation approach.
rust
// Current buggy code in src/api/pagination.rs
fn calculate_offset(page: u32, per_page: u32) -> u32 {
    page * per_page  // BUG: should be (page - 1) * per_page
}
FORGE Writes the Fix
FORGE implements the fix and adds test coverage for the boundary cases.
rust
// Fixed code in src/api/pagination.rs
fn calculate_offset(page: u32, per_page: u32) -> u32 {
    page.saturating_sub(1) * per_page
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_first_page_offset() {
        assert_eq!(calculate_offset(1, 20), 0);
    }

    #[test]
    fn test_second_page_offset() {
        assert_eq!(calculate_offset(2, 20), 20);
    }

    #[test]
    fn test_large_page() {
        assert_eq!(calculate_offset(100, 50), 4950);
    }
}
SENTINEL Reviews the PR
SENTINEL evaluates the changes for correctness, style, and security. It produces a structured review.
json
{
  "review_id": "R-143",
  "pr_number": 143,
  "verdict": "APPROVED",
  "score": 0.92,
  "checks": {
    "correctness": { "pass": true, "notes": "Off-by-one fix is accurate" },
    "style": { "pass": true, "notes": "saturating_sub is idiomatic" },
    "security": { "pass": true, "notes": "No concerns" },
    "testing": { "pass": true, "notes": "3 test cases cover edge cases" }
  }
}
PR Merged
After SENTINEL approval, the PR is merged. LORE records the pattern for future reference. The cycle is complete — from issue to production code, autonomously.
bash
$ openflows status
  Repository: my-org/my-project
  Tasks completed: 142
  Success rate: 94.2%
  Active agents: 4
  Last merge: PR #143 (2 minutes ago)
