Terminal Simulation

Watch Openflows autonomously discover a GitHub issue, plan the implementation, write code, review it, and merge the pull request — all without human intervention.

openflows — my-org/my-project
$ openflows daemon start
✓ Openflows daemon started on port 8080
→ Monitoring 3 repositories
$ openflows repo add my-org/my-project
✓ Repository added: my-org/my-project
→ Scanning for open issues...
[NEXUS] Found 5 open issues. Triaging by priority...
[NEXUS] #142 — Fix pagination bug in API endpoint (HIGH)
[NEXUS] Assigning #142 to FORGE-1...
[FORGE-1] Reading codebase context (src/api/mod.rs, src/api/pagination.rs)...
[FORGE-1] Planning implementation: Fix off-by-one error in page offset calculation
[FORGE-1] Writing code changes...
[FORGE-1] PR #143 opened: "Fix pagination offset in API endpoint"
[SENTINEL] Reviewing PR #143...
[SENTINEL] ✓ Logic correct — off-by-one fix is accurate
[SENTINEL] ✓ Test added — unit test for boundary cases
[SENTINEL] ✓ No security concerns detected
[SENTINEL] Review score: 0.92 — APPROVED
✓ PR #143 merged into main
[LORE] Recorded: pagination bug pattern, offset calculation convention
$ openflows status
Tasks completed: 1 | Tasks in progress: 2 | Agents active: 4
💡 This is a Simulation

This demo plays a pre-recorded session. In production, Openflows reads your real GitHub issues, clones your actual codebase, and writes production code. Try it yourself with the Quick Start Guide.

What You Just Saw

  1. Daemon Start — Openflows launches and begins monitoring repositories
  2. Issue Discovery — NEXUS scans open issues and triages by priority
  3. Task Assignment — NEXUS assigns the highest-priority issue to FORGE
  4. Code Implementation — FORGE reads the codebase, plans a fix, and writes code
  5. Pull Request — FORGE opens a PR with implementation and tests
  6. Code Review — SENTINEL reviews for correctness, style, and security
  7. Auto-Merge — The PR is merged after SENTINEL approval
  8. Knowledge Capture — LORE records decisions for future context
