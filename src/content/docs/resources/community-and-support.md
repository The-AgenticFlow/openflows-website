## Getting help

- **Documentation (this site)** - start here for how-tos and references. The [Guides](/docs/guides) and [Reference](/docs/reference) sections answer most operational questions.
- **Issues** - report bugs and propose features in the project’s GitHub issue tracker. The project and its documentation website live in the OpenFlows repository on GitHub, so its issue tracker is the place to file bug reports and feature requests. Search first to avoid duplicates, and include what you observed vs. what you expected.

> [!INFO] The site shares the project’s issue tracker
> The documentation website is part of the OpenFlows project and points to the same GitHub repository and issue tracker as the product itself - so questions about the docs and questions about the product land in the same place.

## Asking good questions

To get a fast, useful answer:

- **Say what you’re trying to do** - not just the error you hit.
- **Give context** - your setup (tenant and repository), what you expected, and what happened instead.
- **Check escalations** - many “stuck” situations are a ticket waiting on a human decision.

## Staying informed

- Follow the project’s release process to learn about new versions and changes (see [Project Governance](/docs/contributing)).
- Watch the repository for announcements and status updates.

## Building relationships

- The [Contributing](/docs/contributing) section explains how to get involved.
- Whether you’re a user, an operator, or a contributor, the project benefits most from clear, concrete feedback - tell us what works and what doesn’t.
